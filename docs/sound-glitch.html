Sound Glitch: what the later versions fixed

JP 1.0's music loader marks a slot "loading" only after it has queued the file read. If the read finishes first, the flag is left set forever. US and every later version set the flag before the read.

JP 1.0 Flag set after loadFileAsync: a race the load can win.

US · JP 1.1 · PAL · Korean · 3D All-Stars Flag set before loadFileAsync: the race is gone.

Source: the decompiled JAIBasic::checkEntriedSeq, which matches each version's own disc, and the original machine code of each disc.

The function

When the game asks for a new music sequence (a BGM track or a jingle), JAIBasic::checkEntriedSeq finds memory for it and starts an asynchronous DVD read. Each music slot has a mLoadingFlag; while it is set, the function stops working on new requests.

The race

The audio DVD thread runs at a higher priority than the game thread, so it can run as soon as the read finishes, even in the middle of the game thread's code:

gamequeues the read with loadFileAsync and returns DVDread finishes before the game thread runs its next line; the callback sets mLoadingFlag = false and the sound to Prepared gameruns the JP 1.0 line mLoadingFlag = true; no callback is left to clear it laterthe next request on that slot hits if (sud->mLoadingFlag) return;, every frame, until the console is reset

With the US order, the flag is already set when the read starts, so the callback's false is always the last write.

The discs agree

This is the original code from each disc. The store stb r22, 0x3(r30) writes mLoadingFlag (offset 3 of the slot data).

JP 1.1, PAL, the Korean disc and 3D All-Stars have the same function as US, byte for byte apart from addresses.

How it explains the symptoms

Wiki symptomExplanation from the code
Starts for unknown reasonsIt needs a read that finishes while the game thread is held up at that exact point. Pure timing, so it is rare and can happen with or without practice codes.
Lasts until the game is turned offOnly start-up clears the flag.
The Shine jingles don't playThe next track on the stuck slot is never loaded; short jingles such as the Shine-appear and Shine-get music go through these slots.
Cutscenes last at least 6 s (10 s for deaths); Mario frozen after a GatekeeperThe requested track never starts but is never removed either, so the game still sees a secondary BGM in progress, which is the condition the wiki already found for the long cutscenes.
Crashes, often on a ShinePlausible, not proven: the logged crash is a virtual call in JAIBasic::processFrameWork through an overwritten vtable pointer, which fits a sound handle that stays referenced after the rest of the system frees and reuses it. The exact write was not traced.

A second guard in US

US also stops one sound-list walk after 100 entries. That only matters if a list is corrupted into a loop, so it may be part of the same clean-up. JP 1.1 and PAL keep it.
